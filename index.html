Your files, terminals and desktop — over one fast, encrypted link.

WabiLink connects you to your own server: move files at full speed, open a terminal, reach services behind its firewall, and use its desktop with sound — from Windows, macOS or Linux.

One connection, everything on your server

The client logs in once; files, terminals, tunnels and the desktop all travel over that session, encrypted end to end. Only one port needs to be open.

Fast transfers

Files go over several connections at once and are put back together, so a long or lossy link is used to the full. Transfers resume where they stopped.

Shares and live folders

Browse the server's shares like a local disk. Folders update as they change, and a file opened from the server is saved back to it.

Terminals

A shell on the server, or a login over SSH, in a tab of the client — with no SSH port reachable from outside.

Tunnels

Reach a database, a web interface or any TCP service near the server through a local port — the administrator decides who may use which.

Remote desktop, at 60–120 fps

The server's own desktop, built in: coded on its graphics card where it has one, sharp when still, every monitor, sound in step with the picture, and a clipboard that carries text, images and files.

Yours, and secure

Your server, your accounts: per-user rights, the server's identity checked by fingerprint, and every byte encrypted. An admin tool manages it all from your desk.

WabiLink for Windows

Version 1.1.15

The app you connect with. It comes with everything it needs: no installer, nothing else to set up.

  1. Download it

    Most PCs are x64; take ARM64 for a Snapdragon laptop or a Surface Pro X.

    x64 1.1.15 · 75 MB ARM64 1.1.15 · 72 MB

  2. Unpack it

    Right-click the downloaded .zip → Extract All…, and choose where it should live, for example C:\Users\you\Apps. Then open the wabilink-client folder and run WabiLink.exe.

    Right-click WabiLink.exe → Pin to Start to find it again.

    Windows protected your PC? WabiLink is not yet known to SmartScreen. Click More info → Run anyway. It asks only the first time.

  3. Connect

    Click New profile and fill in the server's address (port 8009), your account and password. The first time, WabiLink shows the server's fingerprint: compare it with what the server's administrator got from wabilink-server identity, and accept it.

  4. Video for the remote desktop optional

    The server's desktop is decoded on your graphics card with Windows' own decoders. For HEVC install Microsoft's HEVC Video Extensions, and on Windows 10 the free AV1 Video Extension, from the Microsoft Store. Without them, WabiLink picks a codec you do have.

  5. From the command line optional

    The folder also has wabilink-cli.exe: what the app does, from PowerShell or a script - files, a terminal on the server, tunnels, and the server's desktop (it opens the app's viewer). It uses the app's saved accounts. To type wabilink-cli anywhere, add the folder to your PATH once (the folder you unpacked to):

    [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$HOME\Apps\wabilink-client", "User")

    Then, in a new window:

    wabilink-cli profile add work --host server.example.com --user you
wabilink-cli terminal -p work          # a shell on the server; Enter then ~. leaves one that hangs
wabilink-cli get -p work -r /Files/project .
wabilink-cli help

Updating

Close WabiLink, unpack the new .zip over the old folder, and start it again. Your profiles are kept.

Removing

Delete the folder. Profiles and settings are in %LOCALAPPDATA%\WabiLink.

  1. Download it

  2. Unpack it and start it

WabiLink Server for Windows

Version 1.1.15

Runs as a Windows service: it starts with Windows, restarts if it stops, and shows this PC's own desktop to the people you allow.

  1. Download it

    x64 1.1.15 · 38 MB ARM64 1.1.15 · 36 MB

  2. Unpack it where it will stay

    The service runs from this folder, so put it somewhere permanent. Open PowerShell as administrator (Win+X → Terminal (Admin)) and run:

    Get-Item $HOME\Downloads\wabilink-server-1.1.15-windows-*.zip | Unblock-File
Expand-Archive -Path $HOME\Downloads\wabilink-server-1.1.15-windows-*.zip -DestinationPath "C:\Program Files\WabiLink"
cd "C:\Program Files\WabiLink\wabilink-server"

  3. Install and start the service

    .\wabilink-service install --start

    It runs as LocalSystem; its data and logs are in C:\ProgramData\WabiLink\Server. .\wabilink-service status says whether it is running.

  4. Add yourself and a share

    .\wabilink-service user add $env:USERNAME --admin          # asks for a password, twice
.\wabilink-service share add $env:USERNAME Files C:\Users\Public
.\wabilink-service identity                       # the fingerprint clients will be shown

    Your WabiLink account is named as your Windows account, with a password of its own; Files is the PC's Public folder. Write down the fingerprint: you will compare it the first time you connect.

  5. Open the firewall

    Clients connect on 8009; the admin tool on 8010, which this opens to your local network only:

    New-NetFirewallRule -DisplayName "WabiLink" -Direction Inbound -Protocol TCP -LocalPort 8009 -Action Allow
New-NetFirewallRule -DisplayName "WabiLink Admin" -Direction Inbound -Protocol TCP -LocalPort 8010 -RemoteAddress LocalSubnet -Action Allow

  6. This PC's desktop optional

    Let users see and use this PC's screen from WabiLink, in their session:

    .\wabilink-service config set desktop-enabled yes
.\wabilink-service user desktop $env:USERNAME yes

    That is all on Windows. Viewers see this PC's own screen, UAC prompts included. With nobody signed in - after a restart, or a server with no one at it - it is the login screen, and you sign in from the viewer as at the machine: the viewer's Ctrl+Alt+Del button (the keyboard icon), then a Windows account's password. Where the lock screen asks for no Ctrl+Alt+Del - Windows 11 and 10 by default - press Space or click, as at the PC.

    A session the viewer found at the login or lock screen and signed in to is locked again when the last viewer has gone, so it is not left open on the PC's monitor; one that was already open - someone at the PC, being helped - is left as it was. To leave it open instead: .\wabilink-service config set desktop-lock-on-leave no. Signing in to an account with a disconnected session brings that session to the screen; the viewer follows it.

    For the Ctrl+Alt+Del button, WabiLink lets services send Ctrl+Alt+Del (the SoftwareSASGeneration policy), as remote-support tools do; turning the desktop on sets it, and says so. With a graphics card (NVIDIA, AMD, Intel), the screen is coded on it, at 60 frames a second and more.

    This is the PC's own screen, not a Remote Desktop session: someone connected by Remote Desktop is not seen (the screen shows the login screen meanwhile), and signing in as them from the viewer takes their session over and ends their Remote Desktop connection. For a separate session, use Remote Desktop through WabiLink, below.

  7. Windows Remote Desktop too optional

    On Windows Pro, Enterprise or Education, users can also open this PC's own Remote Desktop (RDP) from WabiLink - Server Desktop (RDP), a separate Windows login - through their WabiLink session, with no RDP port opened to the network. Turn on Remote Desktop in Settings → System → Remote Desktop, then:

    .\wabilink-service config set rdp-enabled yes
.\wabilink-service user rdp $env:USERNAME yes

Is it running?

.\wabilink-service status

Its log is in C:\ProgramData\WabiLink\Server\logs; warnings and errors also go to the Application event log, as WabiLink.

Updating

.\wabilink-service stop
Expand-Archive -Path $HOME\Downloads\wabilink-server-1.1.15-windows-*.zip -DestinationPath "C:\Program Files\WabiLink" -Force
.\wabilink-service start

Removing

.\wabilink-service uninstall

The data in C:\ProgramData\WabiLink\Server is kept; delete it too to remove everything.

WabiLink Server for macOS

Version 1.1.15

Runs as a service: it starts when the Mac starts, before anyone logs in, and restarts if it stops. Copy each box into Terminal as it is - nothing in them needs changing.

You need:
  • macOS 13 (Ventura) or later, Apple silicon or Intel;
  • an administrator account on the Mac: sudo asks for its password. Nothing shows as you type it - type it and press Return;
  • for others to reach it, the Mac on and awake: System Settings → Energy (or Battery → Options) → Prevent automatic sleeping when the display is off.

  1. Open Terminal

    Press ⌘+Space, type Terminal and press Return.

  2. Install the server

    curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/install-macos.sh
sudo bash install-macos.sh

    The first command downloads the install script; read it if you like (less install-macos.sh) before the second runs it. It downloads the newest server for your Mac, checks it, installs it in /usr/local/wabilink-server, and starts it as a service. It ends with "… is installed, running, and starts at every boot."

  3. Make yourself an account

    Your WabiLink account, named as your Mac account, and an administrator. It asks for a password for it, twice - one for WabiLink, which may be different from the Mac's:

    sudo wabilink-server user add "$USER" --admin

  4. Share a folder

    The Mac's shared folder, as Files:

    sudo wabilink-server share add "$USER" Files /Users/Shared
    Sharing your Documents, Desktop or Downloads instead

    macOS protects those folders: the server may read them only once allowed. System Settings → Privacy & Security → Full Disk Access → +, press ⌘+Shift+G, paste /usr/local/wabilink-server/wabilink-server, and turn it on. Then, for example:

    sudo wabilink-server share add "$USER" Documents "$HOME/Documents"

  5. Note the server's fingerprint

    sudo wabilink-server identity

    The app shows it the first time it connects: it should be the same.

  6. Let other computers in

    Only if the Mac's firewall is on (System Settings → Network → Firewall): Options… → +, ⌘+Shift+G, paste /usr/local/wabilink-server/wabilink-server, and set it to Allow incoming connections.

    Other computers connect to this Mac's address, which this shows:

    ipconfig getifaddr en0 || ipconfig getifaddr en1

  7. This Mac's desktop optional

    sudo wabilink-server config set desktop-enabled yes
sudo wabilink-server user desktop "$USER" yes

    Then allow it twice, once, in System Settings → Privacy & Security - in each, +, ⌘+Shift+G, paste /usr/local/wabilink-server/wabilink-server, and turn it on:

    • Screen & System Audio Recording — to show the screen;
    • Accessibility — for the keyboard and the pointer.

    macOS may ask by itself the first time someone connects. After an update it may need turning on again.

    With nobody logged in, viewers see the login window and sign in from it as at the Mac: the account, then its password. A session the viewer found at the login window or locked is locked again when the last viewer has gone; one already open is left as it was. To leave it open instead: sudo wabilink-server config set desktop-lock-on-leave no. With FileVault on, a restarted Mac waits at FileVault's unlock screen before macOS starts: sign in at the Mac once, or restart it with sudo fdesetup authrestart.

Updating

The same commands again: the newest version, the accounts and shares kept.

curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/install-macos.sh
sudo bash install-macos.sh

Is it running?

sudo launchctl print system/com.wabilink.server | grep state
tail -n 20 /Library/Logs/WabiLink/server.log

Removing

sudo wabilink-server uninstall-launchd
sudo rm -rf /usr/local/wabilink-server /usr/local/bin/wabilink-server

The accounts and settings stay in /Library/Application Support/WabiLink; delete that too to remove everything.

WabiLink for Linux

Version 1.1.15

The app you connect with. It brings its own runtime; the system provides fonts, the display and, optionally, video decoders and sound.

  1. Install what it uses from the system

    sudo dnf install fontconfig libICE libSM libicu libdav1d libavcodec-free pulseaudio-utils

    The video decoders come from EPEL:

    sudo dnf install epel-release
sudo dnf install fontconfig libICE libSM libicu libdav1d pulseaudio-utils
    sudo apt update
sudo apt install libfontconfig1 libice6 libsm6 pulseaudio-utils libavcodec-extra
sudo apt install libicu76 || sudo apt install libicu74 || sudo apt install libicu72
sudo apt install libdav1d7 || sudo apt install libdav1d6
    sudo pacman -S --needed fontconfig libice libsm icu dav1d ffmpeg libpulse
    sudo zypper install fontconfig libICE6 libSM6 'libicu??' libdav1d7 pulseaudio-utils

    Fontconfig, libICE, libSM and ICU (libicu, which .NET needs), and for the remote desktop's video dav1d (libdav1d.so.7) and FFmpeg's libavcodec; for its sound pacat or aplay.

    dav1d and libavcodec decode the remote desktop's video; without them it is sent as lossless tiles, which needs a faster link.

    On Arch, for now: its FFmpeg (9) is newer than WabiLink reads, so the remote desktop's video comes as AV1 (dav1d) where the server can send it, and as lossless tiles otherwise.

    openSUSE's own FFmpeg decodes no H.264 or HEVC; dav1d decodes AV1. For all three, FFmpeg from the Packman repository (see the server's instructions).

  2. Download it

    For a Raspberry Pi 3, 4 or 5 with the 64-bit Raspberry Pi OS take ARM64; the 32-bit system has no WabiLink app.

    Most PCs are x86_64; ARM boards and laptops take ARM64. uname -m says which.

    x86_64 1.1.15 · 48 MB ARM64 1.1.15 · 46 MB

  3. Install it for yourself, with a menu entry

    mkdir -p ~/.local/opt ~/.local/bin ~/.local/share/applications
tar -xzf ~/Downloads/wabilink-client-1.1.15-linux-*.tar.gz -C ~/.local/opt
ln -sf ~/.local/opt/wabilink-client/wabilink-client ~/.local/bin/wabilink-client
ln -sf ~/.local/opt/wabilink-client/wabilink-cli ~/.local/bin/wabilink
cat > ~/.local/share/applications/wabilink.desktop <<EOF
[Desktop Entry]
Type=Application
Name=WabiLink
Comment=Files, terminals, tunnels and desktop of your server
Exec=$HOME/.local/opt/wabilink-client/wabilink-client
Terminal=false
Categories=Network;FileTransfer;RemoteAccess;
EOF

    WabiLink is now in your applications menu, and wabilink-client starts it from a terminal; wabilink is its command-line client.

  4. Connect

    Click New profile: the server's address (port 8009), your account and password. Compare the fingerprint shown the first time with the server's wabilink-server identity.

  5. From the command line optional

    wabilink does what the app does, from a terminal or a script - files, a terminal on the server, tunnels, and the server's desktop (it opens the app's viewer) - with the app's saved accounts. If wabilink is not found, log in again: ~/.local/bin is on the PATH from the next login.

    wabilink profile add work --host server.example.com --user you
wabilink terminal -p work              # a shell on the server; Enter then ~. leaves one that hangs
wabilink tunnel -p work db --local-port 5432
wabilink help

Updating

Removing

WabiLink Server for Linux

Version 1.1.15

Installed from WabiLink's signed package repository, so it updates with the rest of the system. It runs as a systemd service under its own wabilink account.

There are no packages for this distribution yet: the server comes as a self-contained archive, which the install script puts in /opt/wabilink and runs as a systemd service under its own wabilink account. The same command updates it.

On AWS? A user data script installs and sets up the server when an EC2 instance first boots: see WabiLink on AWS.

  1. Install it

    curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/install.sh
sudo sh install.sh

    The first command downloads the install script; read it if you like (less install.sh) before the second runs it. It adds the repository and its signing key, then installs wabilink-server with what its optional parts use: ssh for login terminals, the libraries of the remote desktop, and SVT-AV1 for AV1 video where the system has it. It does not start the server yet.

    It picks the 64-bit or 32-bit package by itself (Raspberry Pi 2 and later).

    Or add the repository by hand 
    sudo curl -fsSLo /etc/yum.repos.d/wabilink.repo https://alexander-miglis.github.io/wabilink-packages/wabilink.repo
sudo dnf install wabilink-server
    sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSLo /etc/apt/keyrings/wabilink.asc https://alexander-miglis.github.io/wabilink-packages/wabilink.asc
echo "deb [signed-by=/etc/apt/keyrings/wabilink.asc] https://alexander-miglis.github.io/wabilink-packages/deb stable main" | sudo tee /etc/apt/sources.list.d/wabilink.list
sudo apt update && sudo apt install wabilink-server

  2. Install what it uses from the system

    The server brings its own runtime. From the system it needs OpenSSL 3, and for its optional parts: ssh for login terminals, the X11 and PipeWire libraries for this machine's desktop, pacat for its sound, and FFmpeg and SVT-AV1 for video. The packages for other distributions bring these by themselves; here, install them once:

    sudo pacman -S --needed openssl openssh libx11 libxext libxtst libxfixes libxrandr pipewire libpulse
    sudo zypper install libopenssl3 openssh-clients libX11-6 libXext6 libXtst6 libXfixes3 libXrandr2 libpipewire-0_3-0 pulseaudio-utils libavcodec62

    glibc, OpenSSL 3 (libssl.so.3) and systemd; for the optional parts ssh, libX11, libXext, libXtst, libXfixes, libXrandr, libpipewire-0.3, pacat, FFmpeg's libavcodec.so.59 to .62, and SVT-AV1 2.0 to 3.x (libSvtAv1Enc.so.2 or .3).

    Video coding on Arch, for now: Arch's FFmpeg (9) and SVT-AV1 (4) are newer than this server reads, so this machine's desktop is sent as lossless tiles: sharp, but it needs a fast link (a home network is fine). Files, terminals and tunnels are not affected.
    Video on openSUSE: its own FFmpeg codes only AV1 on the graphics card (NVIDIA RTX 40 and later, AMD RX 7000 and later, Intel Arc), and its SVT-AV1 (4) is newer than this server reads. Other machines send the desktop as lossless tiles, which need a fast link. For H.264 and HEVC from any recent graphics card, use FFmpeg from the Packman repository (a community repository, not openSUSE's own): 
    sudo zypper ar -cfp 90 https://ftp.gwdg.de/pub/linux/misc/packman/suse/openSUSE_Tumbleweed/ packman
sudo zypper dup --from packman --allow-vendor-change
    On Leap, use openSUSE_Leap_15.6 in place of openSUSE_Tumbleweed.

  3. Install it

    curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/install.sh
sudo sh install.sh

    The first command downloads the install script; read it if you like (less install.sh) before the second runs it. It downloads the newest server for this machine's processor (x86_64, ARM64 or 32-bit ARM), checks it against the published checksums, and puts it in /opt/wabilink. It creates the wabilink account and /var/lib/wabilink, the systemd service, and the agent for this machine's desktop. It does not start the server yet. wabilink-server version says which version is installed.

    Or install the archive by hand

    uname -m says which: x86_64, aarch64 (ARM64) or armv7l (32-bit ARM).

    x86_64 1.1.15 · 38 MB ARM64 1.1.15 · 36 MB 32-bit ARM 1.1.15 · 36 MB
    sudo mkdir -p /opt/wabilink
sudo tar --no-same-owner -xzf ~/Downloads/wabilink-server-1.1.15-linux-$(uname -m).tar.gz -C /opt/wabilink --strip-components=1
sudo /opt/wabilink/wabilink-server install-systemd
sudo ln -sf /opt/wabilink/wabilink-server /usr/local/bin/wabilink-server

    This starts the service now and at every boot. --no-same-owner makes the files root's: without it, tar run as root keeps whatever account the archive names, and that account could change the server. Set up the desktop agent by hand too (this machine's desktop, below). To update, run the install script: it takes over an install made by hand.

  4. Add yourself and a share

    sudo wabilink-server user add "$USER" --admin        # asks for a password, twice
sudo mkdir -p /srv/files && sudo chown wabilink: /srv/files
sudo wabilink-server share add "$USER" Files /srv/files
sudo wabilink-server identity                     # the fingerprint clients will be shown

    The service runs as wabilink: it needs to read each share's folder, and write where people upload. For a folder of your own, sudo setfacl -R -m u:wabilink:rwX,d:u:wabilink:rwX /path gives it access.

  5. Start it

    sudo systemctl enable --now wabilink

    systemctl status wabilink shows it running; journalctl -u wabilink -f follows its log.

  6. Open the firewall

    Clients connect on 8009. The admin tool uses 8010: open that only to where you administer from - below, the local network 192.168.1.0/24; put in yours (ip -4 addr shows it).

    sudo firewall-cmd --permanent --add-port=8009/tcp
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port port="8010" protocol="tcp" accept'
sudo firewall-cmd --reload

    If ufw is on (sudo ufw status):

    sudo ufw allow 8009/tcp
sudo ufw allow from 192.168.1.0/24 to any port 8010 proto tcp

    There is no firewall on by default. If you set one up with nftables or iptables, allow TCP 8009, and 8010 from your own network only.

    If a firewall is on (firewalld, ufw, nftables), allow TCP 8009, and 8010 from your own network only; the firewalld and ufw commands are as on Fedora and Ubuntu.

    To reach the server from outside your network, forward TCP 8009 on your router to this machine. Never forward 8010.

    Other computers connect to this machine's address: hostname -I shows it.

  7. This machine's desktop optional

    Lets the people you choose see and use this machine's screen from WabiLink (Server Desktop), inside their encrypted WabiLink session: no other port is opened. Turn it on, and give it to each account that may use it:

    sudo wabilink-server config set desktop-enabled yes
sudo wabilink-server user desktop "$USER" yes

    A small agent runs in each desktop session and offers its screen to the server. The install script sets it up, as the packages for other distributions do. Installed by hand, set it up once:

    sudo tee /etc/systemd/user/wabilink-desktop-agent.service >/dev/null <<'EOF'
[Unit]
Description=WabiLink desktop agent
PartOf=graphical-session.target
After=graphical-session.target

[Service]
ExecStart=/opt/wabilink/wabilink-server desktop-agent
Restart=on-failure
RestartSec=5

[Install]
WantedBy=graphical-session.target
EOF
sudo systemctl --global enable wabilink-desktop-agent.service

    It starts in every desktop session from the next login on; in the session you are in now, at once with systemctl --user start wabilink-desktop-agent.

    Viewers then see whoever is logged in at the machine - locked or not, as on its monitor - and unlock it from the viewer with that account's password. GNOME shows that the screen is shared while someone looks. If someone is working in that session, they are asked first, in a notification naming who asks and from where: Allow or Deny, and no answer in 30 seconds is a no.

    A login screen of your own (GNOME 46 and later: Fedora 40, Ubuntu 24.04, Debian 13, RHEL 10 and newer): give an account desktop-login as well, and a viewer with nobody at the screen - or no screen at all - gets a login screen of its own. It logs in there as any account of this machine, with that account's password, and may log out: the next connection gives a new login screen. Each WabiLink account sees only its own.

    sudo wabilink-server user desktop-login "$USER" yes
sudo wabilink-server login-probe        # whether this machine can
    Without that, lock, don't log out. GNOME doesn't share the login screen on the machine's own screen, so once everyone has logged out there is nothing to show until someone logs in at the machine. Lock instead (Super+L): the viewer shows the lock screen, and you unlock it from there.

    After a restart, nobody is logged in yet. Two ways to have a desktop there from the start:

    • Logged in at boot, locked (any distribution with GDM, GNOME's login screen): GDM logs the account in on the machine's own screen, and WabiLink locks it at once, as Windows shows its locked console. A viewer unlocks it with the account's password; so can someone at the machine. 
      sudo wabilink-server desktop-setup "$USER" --login
sudo systemctl reboot
    • Always on, with no monitor (where GDM includes GNOME's headless session - desktop-setup says if not): a separate GNOME session for the account, started at boot on a 1920×1080 virtual monitor, locked while no one looks and again after each viewer. Don't use it for an account that also logs in at the machine: GNOME runs one session per account at a time. 
      sudo wabilink-server desktop-setup "$USER"

    To undo either: sudo wabilink-server desktop-setup --off.

    Which desktops: GNOME on Wayland, and any desktop in an X11 session. KDE Plasma, Sway and other Wayland desktops are not supported yet: log in to their X11 session where they still offer one (the choice on the login screen).

    Raspberry Pi OS's own desktop (labwc) is not supported yet: switch it to X11 with sudo raspi-config → Advanced Options → Wayland → X11. The screen is sent as lossless tiles.

    Video from the graphics card: with a graphics card, the screen is coded on it - 60 frames a second and more. It needs the card's own driver: NVIDIA's driver for NVIDIA cards (RPM Fusion's akmod-nvidia) (sudo ubuntu-drivers install), and the VA-API driver for AMD and Intel - for H.264 and HEVC on AMD and Intel, RPM Fusion's mesa-va-drivers-freeworld, since Fedora's own leaves them out. The viewer's stats panel (the chart button) says what codes the screen, and why.

Updating

With the system's updates:

sudo dnf upgrade --refresh

A running server restarts by itself.

Updating

With the system's updates:

sudo apt update && sudo apt upgrade

A running server restarts by itself.

Updating

curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/install.sh
sudo sh install.sh

The same commands as installing: the newest version replaces the old one, and a running server restarts. The accounts, shares and identity in /var/lib/wabilink are kept. It takes over an install made by hand too, its files made root's. Desktop agents restart as the new version by themselves.

Is it running?

systemctl status wabilink
journalctl -u wabilink -n 50       # its log; -f to follow it
sudo ss -ltnp | grep -E ':(8009|8010)'

The last shows the ports it listens on. From another computer, the app connecting is the test that counts.

Removing

sudo wabilink-server desktop-setup --off     # only if you used desktop-setup
sudo dnf remove wabilink-server

The accounts, shares and identity in /var/lib/wabilink are kept for a reinstall; to remove everything, also sudo rm -rf /var/lib/wabilink.

Removing

sudo wabilink-server desktop-setup --off     # only if you used desktop-setup
sudo apt remove wabilink-server

The accounts, shares and identity in /var/lib/wabilink are kept for a reinstall; to remove everything, also sudo rm -rf /var/lib/wabilink.

Removing

sudo wabilink-server desktop-setup --off     # only if you used desktop-setup
sudo systemctl --global disable wabilink-desktop-agent.service
sudo rm -f /etc/systemd/user/wabilink-desktop-agent.service
sudo wabilink-server uninstall-systemd
sudo rm -rf /opt/wabilink /usr/local/bin/wabilink-server

The accounts, shares and identity in /var/lib/wabilink are kept for a reinstall; to remove everything, also sudo rm -rf /var/lib/wabilink and sudo userdel wabilink.

WabiLink on AWS

A user data script installs the server on an EC2 instance when it first boots, makes your administrator, shares a folder and starts it - nothing to log in to the instance for. On the Amazon Linux 2023, Ubuntu, Debian, Fedora, RHEL, Rocky Linux and AlmaLinux images, Intel, AMD or Graviton.

Never put a password in user data. Any program on the instance can read it, and so can anyone who can view the instance in the console. The script reads the password from SSM Parameter Store instead, with the instance's own role.

The commands below use the AWS CLI, on your computer, set up with your account (aws configure); each step also says where it is in the AWS console.

  1. Put the administrator's password in Parameter Store

    Console: Systems Manager → Parameter Store → Create parameter: name /wabilink/admin-password, type SecureString, the default key, and the password as its value. Or with the CLI on Linux or macOS - it asks for the password without showing it, and keeps it off the command line:

    printf 'WabiLink admin password: '; stty -echo; read -r pw; stty echo; echo
printf '%s' "$pw" | aws ssm put-parameter --name /wabilink/admin-password --type SecureString --value file:///dev/stdin
unset pw

    On Windows, use the console for this step: its CLI cannot read a value from standard input, and a password typed into the command line itself would be kept in the shell's history.

  2. Give the instance a role that may read it

    Console: IAM → Roles → Create role for EC2, with AmazonSSMManagedInstanceCore and an inline policy allowing ssm:GetParameter on that parameter. Or:

    aws iam create-role --role-name wabilink-server --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ec2.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
aws iam put-role-policy --role-name wabilink-server --policy-name read-wabilink-password --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"ssm:GetParameter","Resource":"arn:aws:ssm:*:*:parameter/wabilink/admin-password"}]}'
aws iam attach-role-policy --role-name wabilink-server --policy-arn arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore
aws iam create-instance-profile --instance-profile-name wabilink-server
aws iam add-role-to-instance-profile --instance-profile-name wabilink-server --role-name wabilink-server

    AmazonSSMManagedInstanceCore is optional, and recommended: with it, Session Manager gives you a shell on the instance with no SSH key or open SSH port, for sudo wabilink-server ... later. With a customer-managed KMS key for the parameter instead of the default, also allow kms:Decrypt on that key.

  3. Open the ports

    A security group allowing TCP 8009 from where your users are (below, anywhere), and the admin tool's 8010 from your own address only, in the region's default VPC:

    vpc=$(aws ec2 describe-vpcs --filters Name=is-default,Values=true --query 'Vpcs[0].VpcId' --output text); echo "$vpc"
sg=$(aws ec2 create-security-group --group-name wabilink --description "WabiLink server" --vpc-id "$vpc" --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id "$sg" --protocol tcp --port 8009 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id "$sg" --protocol tcp --port 8010 --cidr "$(curl -fsS https://checkip.amazonaws.com)/32"
echo "$sg"

    If the first line prints None, the region has no default VPC (accounts set up by an organisation often don't): set vpc= to a VPC of yours that has a public subnet, and add that subnet to the launch below with --subnet-id subnet-.... The instance needs a public address and a route to the internet - to install the server, and to be reached.

  4. Launch the instance with the script as its user data

    The script: ec2-user-data.sh. Its first lines hold the settings - the administrator's name (admin), the parameter, and the shared folder (/srv/files, as Files) - to change if you like.

    Console: EC2 → Launch instance; under Advanced details, the IAM instance profile wabilink-server, and the script in User data. Or, with Amazon Linux 2023 on Intel or AMD (arm64 and a t4g type for Graviton):

    curl -fsSLO https://alexander-miglis.github.io/wabilink-packages/ec2-user-data.sh
aws ec2 run-instances \
  --image-id resolve:ssm:/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 \
  --instance-type t3.small \
  --iam-instance-profile Name=wabilink-server \
  --security-group-ids "$sg" \
  --user-data file://ec2-user-data.sh \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=wabilink}]' \
  --query 'Instances[0].InstanceId' --output text

    A small instance is enough for files, terminals and tunnels; the server takes a minute or three to be set up after boot.

  5. Get the server's fingerprint

    The script writes it to the instance's system log (console: the instance → Actions → Monitor and troubleshoot → Get system log), with its address:

    aws ec2 get-console-output --instance-id i-0123456789abcdef0 --latest --query Output --output text | grep WABILINK

    In PowerShell on Windows - where the CLI needs UTF-8 to print the log at all:

    $env:PYTHONUTF8 = 1
aws ec2 get-console-output --instance-id i-0123456789abcdef0 --latest --query Output --output text | Select-String -CaseSensitive WABILINK

    The server is usually set up a minute after the instance starts; the log can take a few minutes more to show it. Through Session Manager, sudo wabilink-server identity shows the fingerprint at once.

  6. Connect

    In the app: the instance's public address, port 8009, the administrator and its password; compare the fingerprint it shows with the one above before accepting it. An Elastic IP keeps the address the same when the instance is stopped and started.

If it did not finish

The whole run is in /var/log/cloud-init-output.log on the instance (and in the system log). If the password could not be read - the parameter's name, or the role's permission - it stops there: no account is made and the server is not started. Fix it, and run the script again on the instance through Session Manager: sudo bash /var/lib/cloud/instance/scripts/part-001.

Afterwards

More users and shares from the admin tool (port 8010), or through Session Manager. Updates come with the system's own (sudo dnf upgrade --refresh, sudo apt update && sudo apt upgrade). The parameter can be deleted once the instance is set up; the password lives on in the server.

When something doesn't work

The usual causes, and what to do. Commands on the server need sudo on Linux and macOS, and an administrator prompt on Windows (.\wabilink-service in place of wabilink-server).

The app cannot connect

  • Is the server running? Linux: systemctl status wabilink; macOS: sudo launchctl print system/com.wabilink.server | grep state; Windows: .\wabilink-service status.
  • Is port 8009 open in the server's firewall - and on AWS, its security group; from outside your network, forwarded on the router?
  • The right address? On the server: hostname -I (Linux), ipconfig getifaddr en0 (macOS), ipconfig (Windows).

The fingerprint is not the one you expected

Compare it with wabilink-server identity on the server. If they differ, don't accept it: something between you and the server is pretending to be it. If the server was reinstalled without its data, it has a new identity - accept the new one only once the server itself shows it to you.

The password is refused

Set a new one on the server: wabilink-server user passwd NAME. After too many failed tries an account is locked; wabilink-server user unlock NAME clears that.

A share can't be opened, or uploads fail

On Linux the server runs as the wabilink account, which must be able to read the folder, and write where people upload: sudo setfacl -R -m u:wabilink:rwX,d:u:wabilink:rwX /path. On macOS, Documents, Desktop and Downloads need Full Disk Access for /usr/local/wabilink-server/wabilink-server.

A setting was changed, and nothing happened

It was run without sudo: settings belong to the service. Run it again with sudo (on Windows, from an administrator prompt). Settings take effect at once; no restart is needed.

The admin tool cannot log in

It uses port 8010, which the firewall must allow from where you are, and an account made with --admin (or wabilink-server user admin NAME yes).

Server Desktop is greyed out, or says it isn't offered

The desktop is off, or the account may not use it: wabilink-server config set desktop-enabled yes and wabilink-server user desktop NAME yes. The client must be 1.1 or later.

"GNOME does not let its screen be shared here"

Nobody is logged in at the Linux machine, and GNOME doesn't share its login screen. Lock rather than log out; after a restart, log in at the machine once, or set up desktop-setup NAME --login (see the Linux server guide).

"The server's built-in desktop has nothing to show"

No desktop agent runs in a session on that Linux machine. In the session on its screen: systemctl --user status wabilink-desktop-agent, and if it is disabled, systemctl --user enable --now wabilink-desktop-agent. A server installed from the .tar.gz needs the agent set up once (the guide's desktop step).

A black screen in the viewer

The screen is blanked or locked: press a key or move the mouse in the viewer, and unlock it with that account's password. On a Mac, black or no keys means its permissions are off: Screen & System Audio Recording and Accessibility for the server, which an update can turn off again.

The desktop is slow or blurry

The chart button in the viewer's bar shows the codec, frames a second, and why that codec was picked. Lossless tiles need a fast link; for video, the server needs its graphics card's driver (or SVT-AV1), and the viewer its decoders - see the optional steps in your system's guide.

Where the logs are

Linux: journalctl -u wabilink, and the desktop agent's journalctl --user -u wabilink-desktop-agent. macOS: /Library/Logs/WabiLink/server.log. Windows: C:\ProgramData\WabiLink\Server\logs, and the Application event log.
